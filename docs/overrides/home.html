Scripting runtime for automation

A secure runtime for system, infrastructure, and AI agent automation.

Starkite is a modern scripting runtime for automation using the Starlark language. It is shipped as a single static binary with zero setup or additional toolchain to install.

fetch-configs.star 
#!/usr/bin/env kite

def main():
    fleet = ssh.config(
        hosts       = ["web-1", "web-2", "web-3"],
        user        = "deploy",
        key         = "~/.ssh/id_ed25519",
        exec_policy = "concurrent",
    )
    for r in fleet.download("/etc/nginx/nginx.conf", "/tmp/configs/nginx.conf"):
        printf("%s -> %s (%d bytes)\n", r.host, r.dst, r.bytes)

main()
controller.star 
#!/usr/bin/env kite

def reconcile(event, obj):
    if obj.spec.replicas > 10:
        k8s.apply({
            "apiVersion": "apps/v1", "kind": "Deployment",
            "metadata": {"name": obj.metadata.name,
                         "namespace": obj.metadata.namespace},
            "spec": {"replicas": 10},
        })

k8s.control("deployments",
    reconcile = reconcile,
    labels    = "enforce-max=true",
)
weather-server.star 
#!/usr/bin/env kite

def get_weather(city):
    """Return the current weather for a city."""
    forecasts = {
        "san francisco": {"temp_f": 64, "conditions": "foggy"},
        "tokyo":         {"temp_f": 78, "conditions": "sunny"},
        "berlin":        {"temp_f": 52, "conditions": "cloudy"},
    }
    return forecasts.get(city.lower(), {"error": "no data for " + city})

mcp.serve(
    name  = "weather",
    tools = [get_weather],
)

Features

Standard Library

A full set of modules for everyday automation, letting scripts handle local I/O, network, and data work entirely in Starlark.

Infrastructure

Kubernetes built in: manage resources, run controllers and admission webhooks, and generate manifests — all in Starlark, no Go project required.

Agentic Support

Expose scripts as MCP tools for any LLM agent to call, or build your own agent with multi-provider LLM clients and tool calling.

Security

Permission policies and gVisor sandboxing apply to every script — untrusted code runs alongside trusted code without bespoke isolation.

Running Starkite Scripts

1. Run via the kite CLI

Pass any .star file to kite run (or use the implicit shorthand). Use for ad-hoc invocation, CI pipelines, and variable passing.

$ kite run deploy.star

# shorthand — `run` is implicit
$ kite deploy.star --var image_tag=v1.0.0

# pipe results to other tools
$ kite manifest.star | kubectl apply -f -

2. Execute directly via shebang

Add #!/usr/bin/env kite at the top, mark the file executable, and run it like any other script — no kite prefix needed.

$ cat deploy.star
#!/usr/bin/env kite
print("rolling out v1.0.0")

$ chmod +x deploy.star
$ ./deploy.star
rolling out v1.0.0

Built-in Script Testing

Write tests

Test files end in _test.star and define test_* functions. Use the built-in assert(cond, msg), and optionally setup()/teardown() for per-test fixtures. skip() marks a test as skipped.

def test_addition():
    assert(2 + 2 == 4, "basic math should work")

def test_string_contains():
    assert("kite" in "starkite", "starkite should contain kite")

def test_list_length():
    items = ["a", "b", "c"]
    assert(len(items) == 3, "list should have 3 items")

Run tests

kite test discovers every _test.star file under the path, runs each test_* function, and reports pass/fail counts. Add --verbose to see each test name as it runs; the exit code is non-zero if any test fails — CI-ready out of the box.

$ kite test ./tests/
Found 1 test file(s)
============================================================
Tests: 3 passed, 0 failed, 3 total
Time:  9ms
============================================================
